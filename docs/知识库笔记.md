# 知识库配置笔记：让她"现查现答"

> 给大肥鱼接上 AstrBot 知识库（实测于 v4.29.0）：
> 功能手册让她答得准，热梗词典让她接得住朋友的梗。

## 为什么要有它（以及不要放什么）

- **该放**：愿意让她"当众朗读"的公开内容——指令手册、热梗词典、公开设定。朋友们问起，她答得又快又准。
- **不该放**：人格底线 / 防注入规则 / 暗号机制（她会把知识库当"文档"引用——军规不该变成可引用的文档）；
  私密信息（全局库对所有会话可检索，朋友/群都会命中）。
- **私密内容怎么办**：走"会话级绑定"——给特定会话单独指定知识库（见下"会话级绑定"）。

知识库 = "她会什么"；人格 = "她是谁"；livingmemory = "她记得什么"。三件套各管一段，别混。

## v4.29 的接线机制（给愿意折腾的人）

- 文档上传后会**切块**（默认 ~512 字/块）+ 向量化（本项目复用本机 **Ollama bge-m3**，零成本零外传）。
  **条目式文档**（一条一个梗/一条一个指令）检索效果远好于大段散文。
- 每条消息发出前，流水线会拿用户消息去检索（`astr_main_agent._apply_kb`），命中的块以
  `[Related Knowledge Base Results]` 注入上下文——所以不需要重启、不占用人格长度。
- 绑定的两种方式：
  - **全局**：`kb_names: ["大肥鱼手册", "热梗词典"]`（对所有会话生效，改完即时生效——走面板保存或 API）；
  - **会话级**：会话配置里的 `kb_config: {"kb_ids": [...]}`（覆盖全局；想"只给主号开私密库"就用它）。
  - 注：老字段 `default_kb_collection` 在新版已废弃，别再用它。
- 高级开关：`kb_agentic_mode=true` 会改成"给模型一个检索工具、按需查询"，默认关闭即可。

## 三步搭起来（面板操作）

1. 面板 → 知识库 → 新建集合（选嵌入 Provider：本机的 ollama_embedding）
2. 上传 `docs/指令手册.md` 与 `docs/知识库-热梗词典示例.md`（各一个集合，好单独维护）
3. 系统配置 → 把 `kb_names` 填成两个集合名 → 保存（即时生效）

或走 API（适合脚本化）：`POST /api/v1/knowledge-bases` 建库、
`POST /api/v1/knowledge-bases/{id}/documents` 传文件（multipart，字段名 `file`）、
`PUT /api/v1/system-config`（body = 完整配置字典）挂 `kb_names`。
自检：`POST /api/v1/knowledge-bases/{id}/retrieve`，body 要带 `{"query": "...", "kb_names": ["..."]}`。

## 维护节奏

- **热梗会过期**：隔一两周丢一次"新梗"，更新词典文件后**重新上传**（记得删掉旧文档，
  或用文档管理页替换）——用过期梗比不懂梗还尴尬。
- 她学会"新能力"后（装了新插件、写了新指令），顺手把《指令手册》更新同步到知识库。
- 验收小抄：问式自检——检索"kskbl"应命中词典块；聊天里发一句她该会的指令，看答复是否命中手册。
