# 踩坑合集 ⭐

把一只 AI 养进 QQ 里，我们踩过的**所有**坑。每一条都带症状、根因、解法。

---

## 一、QQ / NapCat 侧

### 1. 纯表情消息会被整条跳过（"她装死不回表情"）

- **症状**：用户发 QQ 表情，机器人毫无反应，日志里连报错都没有。
- **根因**：QQ 表情不算文字——纯表情消息的 `message_str` 是**空字符串**，
  上游管线判定"空消息"后静默跳过（日志实锤：`skip llm request: empty message`）。
- **解法**：入站钩子里把 Face 组件翻译成 `[旺柴]` 文本补进 `message_str`（见插件 `inbound_face_to_text`）。

### 2. 视频消息的 file 字段是"光杆文件名"

- **症状**：视频处理全流程静默失败，`ffmpeg rc=-2`（文件不存在）。
- **根因**：NapCat 给视频的 `file` 字段只是一串文件名（无路径无 URL），
  `url` 字段里才藏着 `multimedia.nt.qq.com.cn` 的直链。
- **解法**：多候选解析（url → 本地路径 → `get_file` 凭单提货）+ 下载防伪（检查 `ftyp` 头，防拿回报错网页）。

### 3. QQ 表情有两套编号体系（"打脸发不出去"）

- **症状**：某张脸发送报 `retcode 1200 消息体无法解析`；某些脸"发出来是别的脸"。
- **根因**：社区快照与 NapCat 运行时**编号不通用**（社区"打脸"=279，NapCat 表里根本没有）。
- **解法**：**只信本机运行时表**——`napcat.mjs` 里内嵌着 `JSON.parse('[...]')` 的面部总表，
  挖出来（`grep -o "JSON.parse('\[{\"QSid\"...'"`）当字典；发送用它的 QSid。

### 4. "旺柴"查无此鱼

- **症状**：用户最爱用的 [旺柴]，所有官方字典里都没有。
- **根因**：同一张脸，手机端叫"旺柴"、NapCat 内部叫"**汪汪**"（id=277）。
- **解法**：破案法——让用户手机发一个该表情，日志里读 `[表情:277]`，钉进字典。

### 5. NapCat 连接断线不自愈（"发消息没反应"）

- **症状**：AstrBot 重启/大动作后，NapCat 的 WS 悄悄断掉且**不会自动重连**；重启 NapCat 又会丢登录态要重新扫码。
- **解法**：NapCat WebUI API 自愈——把 websocket 客户端"关一下再开"，**2 秒重连，免扫码**：
  ```
  登录:  sha256(token + ".napcat") → POST /api/auth/login {"hash": ...} → data.Credential
  调用:  Authorization: Bearer <Credential>
  配置:  POST /api/OB11Config/GetConfig → 改 websocketClients[].enable 关→开 → POST SetConfig
         （SetConfig 的 body 是 {"config": "<JSON字符串>"}，注意是字符串！）
  ```
  webui token 在 `napcat/config/webui.json`。做成看门狗每 3 分钟巡检即可全自动。

## 二、AstrBot / 插件侧

### 6. 消息"回声病"：人格指令打不过她自己最近说过的话

- **症状**：她连续 4 条回复都以"我看不太清诶"开头（但细节全报对）；口头禅怎么改人格都复读。
- **根因**：LLM 会**模仿自己最近的发言**（in-context echo）——系统提示干不过聊天记录里的自己。
- **解法**（重要方法论）：
  1. 先试**人格针**（改提示词），不行就立刻换机械层；
  2. **机械橡皮擦**：`on_llm_response` 钩子里按句/按词删掉问题片段，边界要含半角标点防咬边；
  3. **喂料改措辞**：从"[对方发来的视频：…]"改成"[对方发来的视频，**你看得很清楚**：…]"（第一人称感知）；
  4. **记忆手术**：她学的是"她记得的自己"——把记忆里的坏种子剪掉，塞"课程记忆"（见下）。

### 7. "课程记忆"：教她，而不是强迫她

- **思路**：与其在输出端剪，不如往她的长期记忆里写"自己悟出来的课"（用她的口吻、自省句式）。
  例："跟主人处久了，我琢磨明白一件事：关心要恰到好处——提醒一遍就够……"
- **注意**：人格规则里**永远不要列举禁词示例**（"别想大象"效应），LLM 会把你列的禁词原样复读。

### 8. 橡皮擦的三类 bug 与纪律

- **门槛漏算**：链式改写时，`if 有修改:` 的门槛必须把**所有**计数器算上，否则"被冷却丢弃"的片段会以原文裸奔。
- **误伤**：关键词要收窄——"钓鱼"会误伤真聊钓鱼；"不咬"会误伤"我又不咬人"。宁可漏抓，不可错杀。
- **可退役**：机械层是脚手架，稳定期后逐道下线；保留她自己主动配合的机制（暗号、草稿本）。

## 三、大模型 / 百炼侧

### 9. 语音识别走哪扇门

- DashScope 兼容模式**没有** `/audio/transcriptions`（404），AstrBot 原生 whisper_api 路线不通。
- 正确姿势：`MultiModalConversation.call(model="qwen3-asr-flash", messages=[{"content":[{"audio": "file:///本地路径"}]}])`
  ——SDK 自动上传本地文件，还能白拿 `emotion/language` 标注。
- 语音键链：QQ 语音是 silk 编码，用 NapCat `get_record(file=..., out_format="mp3")` 转码后再喂给 ASR。

### 10. 语音合成的情绪与口音

- `qwen-audio-3.1-tts-flash` 支持自然语言指令（`SpeechSynthesizer(instruction="…")`）与语速/音高。
- **血泪结论**：给克隆音色加"撒娇"指令会把**克隆源素材的口音**一起放大；"标准普通话"指令也压不干净。
  最终配方（主观评测 8 个变体后）：**零指令 + 语速 1.04 + 音高 1.0**——没口音又有节奏。
- 音色复刻入口在百炼控制台（体验中心→语音模型→音色复刻），要求音频：≥24kHz、10~20 秒、尽量无 BGM。

### 11. 图片/视频理解链路的"本机化"

让【你本机】下载媒体再交给视觉模型（file:// 上传），比让服务端去取 QQ CDN 链接稳得多。
视频给"前 16 秒抽 4 帧 + 前 60 秒音轨"就够聊天用，成本可控。

## 四、工程杂项

### 12. proactive_chat 的 misfire 雷

定时任务 `misfire_grace_time=60`：迟到 60 秒就被**静默丢弃**。
改大到 3600，或接受"随机排班 + 你一说话就重排"的机制现实。

### 13. Windows 小坑

- `powercfg /setacvalueindex` 里的 `/xxx` 会被 Git Bash 当路径，加 `export MSYS_NO_PATHCONV=1`。
- Python 文件里写 `D:\NapCat\...` 的 docstring 会触发 `\N` unicode 转义错误，docstring 记得 `r"""`。
- Bash heredoc 会吃掉反斜杠和引号——写脚本用文件，别用内联。

### 14. 语音条把 "[旺柴]" 念出来了

- **症状**：她发"文字+语音"双发时，文字里表情正确渲染，**语音却把"旺柴"念了出来**。
- **根因**：TTS 合成跑在表情转换**之前**，合成器不认识方括号标记，当普通文字读了。
- **解法**：在 TTS 合成调用处过滤 `\[[A-Za-z一-鿿]{1,6}\]` 标记（只改合成文本，显示文本保持原样留待表情转换）；
  纯表情段直接跳过合成。

---

### 15. qwen-audio TTS 的两个源码补丁（url error / 语速音高不生效）

- **症状 A**：TTS 模型设为 `qwen-audio-3.1-tts-flash`（自定义复刻音色）后，合成直接失败（url error）。
- **根因 A**：AstrBot 把 `qwen*tts*` 一律路由到「HTTP 多模态」接口，而 qwen-audio 系列实际
  要走 tts_v2 的 **WebSocket**（`SpeechSynthesizer`）。
- **解法 A**：改 `astrbot/core/provider/sources/dashscope_tts.py` 的 `_is_qwen_tts_model`，
  让 `qwen-audio` 前缀改走 WebSocket 路：

  ```py
  def _is_qwen_tts_model(self, model: str) -> bool:
      model_lower = model.lower()
      # qwen-audio-* (含声音复刻音色) 走 tts_v2 WebSocket 接口, 不走 HTTP
      if model_lower.startswith("qwen-audio"):
          return False
      return "tts" in model_lower and model_lower.startswith("qwen")
  ```

- **症状 B**：提供商配置里写了指令/语速/音高，完全不生效。
- **根因 B**：AstrBot 的 dashscope TTS 提供商没把这三个键"接线"（SDK 本来就支持，只是没读、没传）。
- **解法 B**：同文件两处——

  ```py
  # __init__ 里读配置（键写在 cmd_config.json 对应 provider 条目）
  self.instruction = provider_config.get("dashscope_instruction", "")
  self.speech_rate = float(provider_config.get("dashscope_speech_rate", 1.0))
  self.pitch_rate = float(provider_config.get("dashscope_pitch_rate", 1.0))

  # SpeechSynthesizer(...) 调用处传进去
  instruction=self.instruction or None,
  speech_rate=self.speech_rate,
  pitch_rate=self.pitch_rate,
  ```

- ⚠️ **升级 AstrBot 会覆盖这两个补丁，需重打**；接线后的调音结论见第 10 条（M3 配方）。
  完整接线步骤也见 `docs/导入指南.md` 第三节。
