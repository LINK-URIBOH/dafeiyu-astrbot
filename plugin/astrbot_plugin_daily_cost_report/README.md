# 三平台费用日报

每天北京时间 22:00，仅向指定且仍属于 AstrBot 全局管理员的 QQ 私聊发送费用日报。窗口为前一天 22:00 至当天 22:00，使用固定文本，不调用模型、不注册 LLM 工具，也不向长期记忆注入数据。

## 取数及边界

- DeepSeek：官方 `/user/balance`，用人民币总余额差和管理员登记的资金调整计算。`期初余额 + 资金净流入 - 期末余额`。这不是平台费用账单；充值、赠金、退款、失效等应登记，余额增加或负消费提示核对，不截成零。
- 百炼：官方 BSS SDK 5.1.2，`QueryAccountBalance`、`QueryBill`。现金余额和可用额度分别显示。按账单消费时间计入窗口，以 `PretaxAmount` 统计已出账应付费用，含未结清，持续标记暂计；不把实际付款时间当作消费时间。分页完整后原子替换月份缓存，按记录与子订单去重，排除未识别产品。商品名称包含百炼/Model Studio，或明确填写经控制台核对的 `product_codes`。未识别商品的空响应不等于零费用。
- 硅基流动国内站：只读 `https://cloud.siliconflow.cn/walletd-server/api/v1/subject/profile/peek`，使用本人的 Cookie 和 `x-subject-id`；不需要常驻浏览器。它是控制台接口，可能变化。先对照控制台现金余额验证字段与比例；累计消费只有额外对照验证后才启用，否则使用现金余额差。现金和代金券不擅自合并，国外站不可混用。

旧 `/v1/user/info` 不再调用。缺少字段、凭据过期、金额比例未验证、账单时间不足以归属窗口时显示不可获取，不估算、不按比例分摊、不将失败当作零。

每小时与 22:00 采样，边界实际采样偏差超过五分钟即不用于完整日报。首日不追溯余额。历史账单最近七天在下一日报中补正，历史查询可刷新一年内更早窗口。每天只自动发送一次；离线后 08:00–23:00 最多合并补发最近七天一条，23:00–08:00 不补发。发送结果不明标记待确认，不自动重试；明确失败最多三次、间隔至少十分钟。

不同平台可能是总余额、现金及暂计应付等不同口径，报告逐项展示，不作容易误解的统一合计。SQLite、快照、资金调整和发送状态持久化在 `data/plugin_data/astrbot_plugin_daily_cost_report/`，保留一年，应按私密数据备份。

## 管理

在 AstrBot 插件配置中填写 `recipient_qq`（唯一收件人）、`platform_id`（通常 `qq`）、各平台开关、推送开关和采集开关。配置中只填写凭据文件路径，不填写 Key、AccessKey 或 Cookie。

以下命令只允许指定超级管理员私聊；群管理员、其他全局管理员、群内的收件人本人均不能获取费用：

```text
/费用 状态
/费用 今日
/费用 日报 2026-10-28
/费用 刷新
/费用 推送 开
/费用 推送 关
/费用 采集 开
/费用 采集 关
/费用 调整 deepseek +10 2026-10-28T12:30 充值
/费用 调整 deepseek -1 2026-10-28T13:00 失效
/费用 撤销 1
```

调整类型为充值、赠金、退款、失效、提现、调账；资金流入为正数，流出为负数。调整只改变本地统计，不执行任何真实充值或退款。撤销保留审计记录。平台可用 `deepseek/ds`、`siliconflow/sf/硅基流动`；百炼直接按账单统计，不登记余额差调整。

关闭推送继续采集，期间日报标记为停推，重新打开不补发停推期间日报。关闭采集不补造缺失快照。`/费用 刷新` 不额外发送日报；`今日` 和 `日报` 只向命令发起者返回结果。

## 凭据

将 `credentials.example.json` 的内容保存到服务器私密目录，例如 `/run/secrets/daily-cost-report.json` 的只读挂载源，权限 600。DeepSeek 默认读取现有 `DEEPSEEK_API_KEY` 环境变量。

百炼 RAM 使用独立身份，最小读取策略：

```json
{"Version":"1","Statement":[{"Effect":"Allow","Action":["bssapi:QueryAccountBalance","bssapi:QueryBill"],"Resource":"*"}]}
```

硅基流动使用国内控制台中本人钱包 `profile/peek` 请求的完整 Cookie、`x-subject-id`。初次填写控制台人民币现金余额到 `reference_cash_balance_cny`，默认比例 `0.000000000001` 仅为待验证候选；必须通过对照才使用。若填写累计消费参考值，也会校验后再启用该字段。映射和账户标识变化会重新校验。接口只允许两个固定官方域名，不跟随重定向，密钥不出现在查询字符串和日志中。

更新 Cookie 时应原位写入服务器挂载源文件（保留 inode），或重新创建 AstrBot 容器以更新绑定；随后私聊 `/费用 刷新`。不读取浏览器密码库，不自动绕过验证码。

## fnOS 增量安装

见 `deploy/fnos/compose.cost-report.yaml`、`Dockerfile.cost-report` 及 `tools/install_cost_report.py`。以现有已验证 AstrBot 镜像为基础，在 `/opt/dafeiyu-cost-sdk` 独立虚拟环境安装官方 SDK，通过 `DAFEIYU_COST_SDK_PYTHON` 指定解释器。SDK 仅接收标准输入中的一次只读请求，不经命令行传递密钥。构建时校验核心 `pip freeze` 完全不变，并分别运行两个环境的 `pip check`；不重新初始化核心或其他插件。

1. 构建新镜像，先在 `/tmp` 中运行插件测试；源码、测试不含真实凭据。
2. 运行现有完整备份及隔离解包检查，保存旧镜像 ID 和 Compose。
3. 仅停止新 AstrBot，执行安装脚本，传入已验证备份、插件源码及受限凭据输入文件；脚本只复制此插件和设置此插件配置。
4. 用原 Compose 及费用覆盖文件重新创建 AstrBot，原局域网绑定照常保留。检查 OneBot、插件状态，再做管理员私聊试报。
5. 后续启停、重建时保留费用覆盖文件参数；备份包含全部 `astrbot/data`、`secrets` 以及覆盖文件和依赖锁。

不填写凭据的平台可以保持未配置状态，其他平台继续工作。回滚时禁用插件并恢复旧镜像/Compose，保留费用数据库以便以后恢复。

## 测试

在已安装依赖的 AstrBot 镜像中执行：

```bash
PYTHONPATH=/path/to/plugin-parent:/AstrBot python -m unittest discover -s /path/to/astrbot_plugin_daily_cost_report/tests -v
```

覆盖精确小数、时间与跨月、边界快照缺失、调整与撤销、延迟补正、账单分页和去重、控制台金额验证、缺失字段、登录失败、重启、去重、夜间合并补发，以及真实 AstrBot 命令权限过滤。测试不发送真实 QQ 消息、不调用模型。
