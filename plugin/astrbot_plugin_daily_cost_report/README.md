# 三平台余额日报 v1.1.0

每天北京时间22:00，只向指定且仍在全局管理员名单中的QQ私聊发送余额变化。窗口为前一天22:00至当天22:00；固定文本，不调用模型、不注册LLM工具、不写入长期记忆。

## 明确展示余额变化

各平台展示“增加／减少／未变化”和“期初余额 → 期末余额”，不再把余额差说成本期调用费用。

- DeepSeek：官方 `/user/balance` 的人民币现金＋赠金总余额。
- 阿里云账户（百炼等）：官方 `QueryAccountBalance` 的 `AvailableCashAmount`。这是全账户现金，包含其他云产品，不能称为百炼独立消费；可用额度只在状态查询展示，不参与计算。
- 硅基流动：国内钱包接口经用户核对的现金余额，不含代金券；即使累计消费字段已验证，新版主统计也不自动切换口径。

差值为期末减期初。充值、退款等登记仅作说明，不修正这个差值，不估算消费。非零变化小于四位小数显示精度时写“增加／减少不足￥0.0001”，不误称未变化。

余额变化不等同于本期调用费用，阿里云扣款可能滞后。不同余额类型不作统一合计。正常日报不逐项列采样秒数或重复技术说明；异常和资金事件在对应平台下说明。

## 边界与历史保护

每小时及22:00采样。完整日报要求两端实际采样偏差不超过五分钟、账户和币种一致；缺失时指出期初／期末缺失，不用旧余额顶替或显示零。`今日`用期初22点快照和最近五分钟内成功的样本，注明截至当前采样、窗口未结束。

首次加载v1.1.0时，持久记录**上线后的下一个22:00**为首个新版日报截止时间；重载和重启不会移动它。之前已保存的日报按原版本、金额、文案和发送记录保留。历史查询只读，不刷新、不重算、不补发；没有保存的旧日报也不追溯补造。

新版窗口保留最近七天缺样补齐的修正、08:00–23:00合并补发与发送去重；不把旧费用修正混入新余额日报。不明确回执不盲目重试，明确发送失败最多三次、至少间隔十分钟。停推仍采集且不补发停推窗口，停采不补造快照。SQLite及审计数据保留一年，纳入现有私密备份。

## `/费用` 命令不变

仅指定超级管理员私聊可操作；其他管理员、群管理员、普通成员及群内的收件人本人均不能查询。

```text
/费用 状态
/费用 今日
/费用 日报 2026-11-20
/费用 刷新
/费用 推送 开
/费用 推送 关
/费用 采集 开
/费用 采集 关
/费用 调整 阿里云 +10 2026-11-20T12:30 充值
/费用 调整 deepseek -1 2026-11-20T13:00 失效
/费用 撤销 1
```

平台别名：`deepseek/ds`、`bailian/百炼/阿里云`、`siliconflow/sf/硅基流动`。类型为充值、赠金、退款、失效、提现、调账；资金进入填正数，失效或提现填负数。登记和撤销保留审计，不执行真实支付，不改变余额差或冻结的历史日报。

`状态`显示开关、首份新版截止时间、最后成功采样、余额、阿里云可用额度及错误。`刷新`不额外推送，`今日`和历史查询只回复指定管理员。

## 凭据、升级与回退

复用现有受限凭据及BSS SDK独立环境，无新增依赖或权限。DeepSeek读取既有环境变量；RAM和硅基流动登录态使用600权限文件只读挂载，不写入面板、日志、URL或模型请求。

日常采集不再调用 `QueryBill`；旧缓存保留，不把跨天累计账单分摊成22点窗口费用。已有账单读取权限可以保留，本次不自动修改RAM策略。

硅基流动只请求固定国内官方钱包地址，不跟随重定向；字段和单位须对照控制台验证。更新Cookie时保留挂载源inode，或重建容器后再 `/费用 刷新`；不自动登录或处理验证码，不调用旧 `/v1/user/info`。

升级前一致性备份插件、配置和SQLite并验证副本。仅更新此插件并通过AstrBot插件重载入口加载，不初始化配置、不更新核心/其他插件/QQ服务。随后验证三平台采集、历史记录不变、命令和一次明确标记的私聊试报。

回退前先停用插件，保留当前费用数据库和发送记录。首份新版记录尚未生成时可恢复旧代码后重载；已有新版日报时不要直接让旧代码重算同一个数据库，须审查兼容性或保持停用，不能用旧数据库覆盖新数据。

验证方法见 [VALIDATION.md](VALIDATION.md)。
